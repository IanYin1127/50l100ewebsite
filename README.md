# 慧湖50L100E · 平台运行监控

面向高校、科研院所的平台运行监控工作台，基于官方公开信息追踪成果产出、活动动态、来源可达性与待核实事项。网站使用原生 HTML、CSS、JavaScript，采集任务由 GitHub Actions 每日运行。

## 页面结构

- **运行总览（默认首页）**：平台总量、官方来源配置覆盖率、过去 365 天有公开动态的平台数、已收录动态数；优先核查来源异常、长期未见动态和待补来源的平台。
- **平台监测台账**：支持关键词、高校、状态筛选与排序，桌面每页 15 个、手机每页 5 个平台；展开行查看来源依据、动态与人工核验记录，跳转到完整平台档案。
- **成果与动态**：默认展示筛选范围内最近 6 条，支持展开全部，保留原文日期、链接、来源和收录记录。
- **采集来源**：显示已检查的官方栏目及其检查结果。
- **平台档案、资源分布、重点实验室、数据维护**：作为辅助模块保留。

园区高等教育教育科技人才三位一体 2024—2026 政策不再在网站展示。旧的 `#policies` 链接回到运行总览；历史原始数据仍留存，不参与前端展示。

监测展示的是公开运行线索：无动态或来源不可访问不直接等于停运。台账只在有依据的人工核验后显示确认运行／停运，核验有效期和来源配置规则见 [监测维护说明](monitoring/README.md)。

## 文件与预览

- `index.html` / `styles.css` / `app.js`：工作台布局、交互与样式。
- `data.js`：平台基础档案、实验室等原始数据。
- `monitoring-data.js`：前端使用的监测记录与公开动态。
- `scripts/collect_updates.py`：Python 标准库采集器。
- `monitoring/`：官方来源配置、人工补录、采集快照与维护说明。
- `.github/workflows/platform-monitor.yml`：每日采集与 Pages 发布。

```sh
python -m http.server 8080
# 打开 http://localhost:8080
node --check app.js
python -m unittest discover -s tests -v
```

## 发布与采集

生产分支为 `main`。每日 UTC 00:17（北京时间约 08:17）以及主分支推送会触发采集、保存和 Pages 发布，GitHub 调度可能延迟。也可在 Actions 中手动运行“平台动态采集与网站发布”。已配置的 Pages 环境通过 Actions 上传产物并发布，检查 collect/deploy 两个任务是否成功。

页面显示实际采集时间，超过三天未刷新会提示检查任务。指标读取真实数据，不生成模拟增长趋势。覆盖率表示配置了官方来源的平台比例，不代表对应平台均已确认运行。

## 更新基础档案

1. 使用根目录 `平台资源清单-更新模板.xlsx` 整理资源字段。
2. 在“数据维护”输入原有维护密码解锁，在本地浏览器中导入 Excel。
3. 生成并下载 `data.js`，替换仓库中的同名文件。
4. 同步核实 `monitoring/sources.json` 中的 ID、名称、高校与来源归属后提交 PR。

Excel 解析通过 CDN 加载 SheetJS，文件不上传到服务器。前端密码仅是维护入口限制，不是服务端鉴权。导入只更新资源，保留原始数据其他字段；身份校验可防止复用序号导致历史成果错配。

成果分享与状态反馈入口打开 GitHub Issue 表单，需要 GitHub 账号。维护者核实后补录或修正，未确认信息不直接发布。
